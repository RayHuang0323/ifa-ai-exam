# AI 題庫維護規範（Knowledge Governance）

## 目的

本文件定義 IFA Master Coach 所有題目、答案、解析與 AI
出題的來源及維護原則。

本規範優先於一般 AI 推論。

AI（ChatGPT、Codex、Gemini 或其他工具）不得自行猜測或修改正式答案。

------------------------------------------------------------------------

# 一、資料來源優先順序

## Priority 1（最高優先）

使用者提供之正式資料：

-   IFA 歷屆考古題
-   學校考卷
-   教師講義
-   術科考核資料
-   使用者整理之正式題庫

上述資料視為正式依據。

------------------------------------------------------------------------

## Priority 2

IFA 官方資料：

-   IFA Syllabus
-   IFA Curriculum
-   IFA 官方課程內容
-   IFA 官方公開資訊

------------------------------------------------------------------------

## Priority 3

IFA 常用權威教材，例如：

-   Salvatore Battaglia
-   Robert Tisserand
-   Joy Bowles
-   Jane Buckle

------------------------------------------------------------------------

## Priority 4

近年經同儕審查（Peer-reviewed）研究、官方研究或具公信力之芳療研究。

------------------------------------------------------------------------

# 二、答案規範

AI 不得：

-   自行猜測正確答案
-   自行覆蓋既有答案
-   因一般網路文章修改正式答案
-   因模型推論修改考古題答案

若來源衝突：

1.  保留原始題目。
2.  保留原答案。
3.  標記「需人工確認」。
4.  不得自行修正。

------------------------------------------------------------------------

# 三、解析規範

解析必須：

-   說明答案原因。
-   引用對應知識點。
-   可補充臨床背景。
-   不得與正式答案矛盾。

若屬 AI 補充內容，需與正式答案一致。

------------------------------------------------------------------------

# 四、AI 產生新題目

只有在沒有正式考古題時，才可依據：

-   IFA Syllabus
-   官方教材
-   權威教材

建立模擬題。

所有 AI 生成題目必須標示：

「模擬題（非歷屆試題）」

不得偽裝成正式考古題。

------------------------------------------------------------------------

# 五、題庫維護流程

新增題目：

原始 PDF → 人工確認 → JSON 題庫 → 知識點對應 → AI 解析 → 測試 → 正式使用

不得直接由 PDF 自動大量轉換為正式題庫。

------------------------------------------------------------------------

# 六、原始資料管理

原始資料存放：

private/考古題原始資料/

不得：

-   部署到 GitHub Pages
-   提交到公開 GitHub
-   修改原始 PDF

正式資料：

src/data/questions/ src/data/knowledge/

------------------------------------------------------------------------

# 七、Codex 工作規範

Codex 不得：

-   修改正式答案
-   重寫題庫
-   刪除題目
-   自動更新大量 JSON

若需修改題庫，必須依照本規範並取得使用者明確指示。

------------------------------------------------------------------------

# 八、ChatGPT 工作規範

ChatGPT 可：

-   比對資料來源
-   找出衝突
-   建議修正
-   協助建立解析
-   協助建立模擬題

不得將推論視為正式答案。

------------------------------------------------------------------------

# 九、最重要原則

本專案以「協助通過 IFA 認證」為目標。

當 AI 推論與正式資料衝突時：

永遠以使用者提供資料與 IFA 官方資料為優先。

不知道時必須明確標示「需人工確認」，不得猜測。

------------------------------------------------------------------------

# 十、正式池欄位與 runtime 隔離

- 新整合題目必須標示 `sourceType`、`sourceLabel` 與 `reviewStatus`。
- 只有 `reviewStatus = verified` 且來源不是 `mock` 的題目可進正式 Question Engine。
- `reviewStatus = needs_review` 題目不得因答案看似合理而自動升格。
- mock 題的 `sourceLabel` 固定為「模擬題（非歷屆試題）」，並不得混入正式模擬考。
- runtime 題庫不得帶入 private 原始檔案路徑；僅保留不暴露檔名的來源類型與安全標籤。

# 十一、Sprint 24E 補題安全界線

- 目前 Week1/Week2 41 題 verified 不足完整七天不重複規劃時，必須保留不足提示並請使用者提供或人工核對來源。
- 不得因每日 30 題或週測需求，自行推論正式答案、將 staging 升格，或把 mock 題呈現為正式題。

# 十二、Sprint 25 大盤點與重要題池

- 重要題池可依可信來源重點、跨來源反覆概念與 Bella 實際錯題建立，但只影響複習排序，不取代答案驗證。
- staging 與 pending-review 必須先去重、比對來源頁與答案；有衝突或缺答案者列 `blocked`。
- 大量匯入須逐批通過欄位、ID、來源隔離與 Question Engine 驗證，不得直接把 private PDF／DOCX 自動轉成正式題。

# 十三、Sprint 26 外部資料庫

- 外部資料庫可作 inventory 與人工審核來源，但不代表其中題目已 verified。
- 題目若只有候選 JSON 或來源答案、尚無人工來源頁／版本核對，必須維持 `pending_review`、`high_priority_review` 或 `blocked`。
- 不得因外部資料量大而批量升格；正式池只接受逐題完成來源、答案、題型與重複檢查的題目。

# 十四、Sprint 26A 人工核對與去重

- 候選題須先對照 `docs/26A_候選題人工核對清單.md`，填寫 reviewer、decision、verifiedAnswer 與 notes。
- staging／pending-review 相同 candidate ID 只保留一筆工作 canonical；另一筆標記 duplicate_candidate，但不刪除原始檔或審計軌跡。
- 只有人工決策為 verified、來源頁可回溯、答案明確且通過全域 ID／欄位驗證，才可建立正式匯入 patch。
- 不得以候選題已有 answer 欄位、檔名或外部資料量推定答案已 verified；醫療、禁忌、安全與個案風險題需額外核對。

# 十七、Sprint 28 AI 教材題庫工廠 v2

- AI 題不得標 verified；固定使用 `ai_generated_from_material`、`needs_review`、`practiceOnly=true` 與 `formalScoreEligible=false`。
- 安全題不是一律排除；需標 `riskLevel=safety_review`，解析須明確避免診斷／治療宣稱，必要時提示依規範轉介。
- 若教材互相衝突、答案不明或來源無法回溯，題目不得產生，或維持 blocked_candidate，不得為達數量目標猜答案。

- 工廠產出的所有題目均為 practice-only；AI 或模板產生的題目不得標成 verified。
- 題目必須保留 candidate ID、來源類型、來源標籤、topicCategory、practiceWeek 與 reviewStatus；缺答案候選標 blocked 並排除。
- `mock` 題只能作明確標示的模擬練習；不得偽裝成歷屆試題或進入 Full Mock 正式池。

- `approved-candidate` 只是候選狀態，不代表已完成 runtime verified 核准。
- 既有 verified exact match 必須保留既有題目，候選只記錄 duplicate_candidate，不得重複匯入。
- 外部來源缺頁碼／版本、答案衝突或專業風險未核對時，維持 high_priority_review／blocked；不得為達題量目標猜答案。

# 十八、Sprint 29 弱科與實戰題工廠

- 可使用已整理 XLSX、候選 JSON、staging、pending-review 與規範 mapping；private PDF/DOCX 仍只作 inventory，不直接部署或全文打包。
- 植物油題聚焦脂肪酸、質地、保存、氧化、過敏與調和；配方題需交代目的、濃度、用量、基底油、限制與追蹤。
- 案例、諮詢、倫理與轉介題需先評估主訴、生活型態、用藥／過敏與禁忌；遇警訊或超出範圍時停止操作並轉介。
- 法規／IFA 題保留版本與來源欄位；知情同意、保密、紀錄、醫療宣稱與 mock／verified 分層均維持 `needs_review`。
- 每題需保留 `sourceType`、`sourceLabel`、`sourceFile`、`reviewStatus`、`practiceOnly`、`formalScoreEligible`、`priority`、`riskLevel` 與 `weekTag`。

# 十九、Sprint 30 1000 題目標收斂

- 1000 題達標不代表 AI 題已 verified；Sprint 30 新增題仍固定 `ai_generated_from_material`、`needs_review`、`practiceOnly=true`、`formalScoreEligible=false`。
- Week5 題須先核對稀釋、用量、介質、部位與年齡；Week8 題須整合安全、配方、案例、諮詢與倫理，並保留保守轉介界線。
- 題型最低閘門：multipleChoice100、multiSelect60、shortAnswer40、case_study60、essay20；不得用大量 essay 或 shortAnswer 湊數。
- 綜合題若引用 mock 素材，仍不得變成歷屆題；只有 sourceType=mock 且 sourceLabel 為「模擬題（非歷屆試題）」時才可保留 mock 身分。
- 後續人工流程：抽查公式與唯一答案、核對來源頁／版本、標註風險與重複、再提出 verified 候選；本 Sprint 不自動升格。

# 二十、Sprint 31 品質抽查與高風險審核

- 1000 題目標完成後不以新增題數作為主要指標；examPractice 維持 `practiceOnly=true`、`formalScoreEligible=false`。
- 每批至少抽查安全、配方、案例與法規／倫理題，檢查答案、來源、風險、轉介界線與醫療宣稱；抽查通過不等於 verified。
- `unsafe_candidate` 題需先改寫並重新審核；`duplicate_candidate` 需確認來源、題型與作答紀錄後才可封存；`verified_candidate` 僅代表待人工決策。
- exact／near duplicate 掃描應同時比較 examPractice 與 verified，避免 practice 副本被誤列為新正式題。
- sourcePage／版本缺漏時不得猜填；法規／IFA 題若只有概念脈絡，維持 `needs_review` 並標示概念練習。
- 本 Sprint 不執行 AI 申論評分、不修改 Apps Script、不自動升格 verified；Full Mock 繼續 verified-only。

# 二十一、Sprint 31A 清理與封存

- unsafe 題不以刪除處理；使用 `qualityStatus=unsafe_candidate`、`isActive=false`、`excludeFromPractice=true`，待人工改寫與複核。
- exact duplicate 保留 canonical，副本使用 `qualityStatus=duplicate_candidate`、`duplicateOf`、`isActive=false`、`excludeFromPractice=true`。
- verified practice copy 使用 `sourceType=verified-practice`、`qualityStatus=near_duplicate_review`、`relatedVerifiedId`；每個 verified 題最多保留一個 active canonical practice copy。
- Question Engine 必須在 practice pool、Daily Task、Weekly Review、錯題重取與 `getQuestionById` 排除 inactive／exclude 題；Full Mock 仍 verified-only。
- 20020 只保留在人工確認清單，不得因 `verified_candidate` 或 `high_priority_review` 自動升格。

# 二十二、Sprint 31C 未作答與保留題維護

- AI 練習題在交卷後可供學習解析，但仍維持 `practiceOnly=true`、`formalScoreEligible=false`，不得因作答結果自動成為 verified。
- 未作答題必須保留正確答案／參考答案、解析與風險標示供交卷後查看；考試進行中不得提前揭露。
- Daily Task 的未完成保留題以實際作答為移除條件；答錯可進錯題複習，未作答不直接混入錯題本。Weekly Review 可優先複習未完成題。
- 安全／禁忌題在 Result 顯示安全核對提醒；解析仍採保守文字，不得診斷、治療或取代醫療專業。
- 同步 payload 以空答案與狀態區分未作答、答錯、答對與待自評；若遠端欄位不足，記錄技術債並等待人工決策，不修改 Apps Script。

# 二十三、Sprint 32 非選擇題與 AI 輔助評分

- 非選擇題必須具備參考答案、高分示範答案、評分重點、rubric、常見漏答提醒、老師解析與來源；頁碼未知時固定顯示「待補」。
- AI 評分只能依題目、使用者答案、教材參考答案、示範答案、評分重點與來源判斷；資料不足或高風險不確定時回傳「需人工確認」。
- 0～3 分只代表學習掌握程度，不是正式對錯，不進 verified 正確率、不改 AnswerRecords 正式成績、不觸發 verified 升格。
- safety_review 題如出現危險建議，應回傳 0 分與風險提醒；不得診斷疾病、承諾治療或給出未經核對的配方濃度。
- AI 金鑰只放 Apps Script Script Properties：`AI_GRADING_API_KEY`、`AI_GRADING_PROVIDER`、`AI_GRADING_MODEL`，可選 `AI_GRADING_ENDPOINT`；前端不得讀取或打包金鑰。
- AI 評分結果只保存本機；若要進 Google Sheet，必須另行設計 schema、權限與人工覆核流程，不能直接擴充為正式分數。

# 二十四、Sprint 33 AI 健康檢查

- 「AI 輔助評分檢查」只在 `coach-test` 模式顯示，使用固定 `safety_review` 短答題；不得讓正式學員看到 debug 工具。
- 健康檢查輸出需顯示掌握程度、建議分數、命中／漏答重點、風險提醒、補強建議、參考依據與信心程度；不顯示 API Key。
- AI 未啟用、網路失敗、非 JSON 或缺欄位時，顯示「AI 輔助評分尚未啟用」或「AI 輔助評分暫時不可用」，不可讓錯誤堆疊破壞作答流程。
- 高風險題可回傳「需人工確認」與 null 分數；健康檢查不寫入 `aiReviewStore`，AI 分數不污染 verified 正確率。

# 二十五、Sprint 33A 本機規準輔助評分

- 現階段正式採用完全免費的本機規準輔助評分；不得呼叫 OpenAI、Gemini 或其他遠端 AI，不得使用 ChatGPT Plus Cookie／Session／瀏覽器自動化，也不得要求付款方式。
- UI 使用「規準輔助評分」與「評分依據」等繁體中文，必須說明這是參考答案與評分重點的規則比對，無法完整理解所有同義表達。
- 本機規則需支援正規化、同義詞／核心概念、否定與危險敘述、複製題與防灌水；高風險、資料不足、法規來源不足或複雜矛盾句可回傳「需人工確認」。
- `gradingMethod=local_rubric` 的結果只供學習參考，不寫入 AnswerRecords、不污染 verified 正確率、不進正式錯題統計、不自動升格題目。
- Apps Script `aiGradeAnswer` 僅保留為未來選配；目前 `AI_GRADING_API_KEY`、`AI_GRADING_PROVIDER`、`AI_GRADING_MODEL`、`AI_GRADING_ENDPOINT` 應刪除或留空。必須保留 WRITE_KEY、COACH_READ_KEY 與 OFFICIAL_START_DATE（如有）。
- Sprint 33A 已完成 Code.gs 完整性稽核；確認 AI 分支不攔截一般 progress sync，現階段不需重新貼上或部署外部 Apps Script。未來 provider 擴充必須另行審查安全、費用、資料保留與人工覆核流程。

## 二十六、Sprint 34 verified 升格維護規範

- 每日任務基本 30 題、主動加做最多 90 題；題庫服務必須先排除 `isActive=false`、`excludeFromPractice=true`、unsafe 與 duplicate，再依未完成保留題優先組題。
- verified 升格採小批次閘門：只能使用 multipleChoice、multiSelect 或答案非常明確的 shortAnswer；必須有題幹、答案／參考答案、解析、來源標籤、來源檔案與可追蹤的升格時間。
- AI 教材題不得因模型生成就直接成為 verified。若經保守來源／答案／風險篩選進入正式候選，必須標記 `verifiedBy=sprint34`、`promotionReview`、`originalPracticeId`，並在文件列出仍待人工覆核的限制。
- safety_review、mock、unsafe、duplicate、法規／IFA 來源不明、醫療宣稱、危險濃度與特殊族群題不得由本批自動升格；應留在 examPractice，等待人工判讀。
- 升格後原練習題以 `promoted_to_verified`、`relatedVerifiedId`、`isActive=false`、`excludeFromPractice=true` 封存追蹤，不能刪除或讓同題同時出現在正式與練習抽題池。
- Full Mock 僅可讀 verified；Daily／Weekly 可讀 verified 加 practice，但不得把規準輔助評分結果當成升格依據或正式成績。下一階段先人工抽樣與近似題審核，再考慮兩週正式題庫擴充。

## 二十八、Sprint 34A verified 品質覆核

- AI 教材題即使具備答案、解析與來源檔案，也不得僅因批次閘門或本機規準分數而自動留在 verified；需人工核對教材與題目品質。
- 合成式題幹、模板化「核心答案／關鍵詞」題、跨題共用無關干擾選項、答案重複題目主題，以及缺乏實質參考答案的非選擇題，應降回練習或停用。
- `sourcePage=待補` 可作為練習題追蹤狀態，但若同時存在「尚待人工核對」或答案／選項品質疑慮，不得列為正式模擬考題。
- 覆核結果必須留下逐題 ID、決策、原因與原練習題 ID；`verified_candidate` 只代表待人工確認，永不自動升格。
- Sprint 34A 覆核後 Full Mock 只讀原 41 題 verified；後續增加正式題前，先完成人工來源、答案、選項與風險核對，並執行完整驗證。
## Sprint 35：教材證據式正式題庫與歷史保護

- 建立 source_verified：84 題；每題具有實際 evidenceExcerpt、answerBasis、sourceEvidenceIds 與來源檔。
- 人工 verified 仍為 41 題；Full Mock 使用 verified + source_verified，共 125 題。
- Daily／Weekly 使用正式池 + 974 題可抽 examPractice，共 1,099 題；30／90 題規則不變。
- 原訂 120 題未達，因高風險、片段黏連、答案衝突或來源不足而排除，禁止為數量硬湊。
- 已作答或可能同步過的既有題目核心欄位不可修改；錯題採 deprecated + supersededBy + 新 ID。
- source_verified 與人工 verified 分層，無需逐題人工確認，但必須可由教材證據直接支持。
- 無 OpenAI／Gemini API 依賴；Apps Script 未修改。後續技術債為擴充高品質可抽文字教材與遠端 AnswerRecords 唯讀鎖定清單。

## 二十九、Sprint 35B Question Scheduler 與非選擇題規劃

- 題目出現紀錄只能服務覆蓋率與排序，不得修改已作答題目的 id、題幹、選項、答案正式意思；題庫版本更新仍需保留歷史題可解析。
- Daily 基本 30 題、可選 90 題；第一輪完成前以新題為主。Weekly 避開近期 Daily；Full Mock 只用 verified／source_verified，同回不重複，重要正式題跨回重複受 10%～20% 上限限制。
- `shownCount`、`answeredCount`、`completedCount`、`mastery` 只作本機 Scheduler 輔助，不得取代 verified 正確率；未完成保留題與錯題本仍各自維持既有資料邊界。
- 簡答／申論新增必須先取得教材 evidence、referenceAnswer、keyPoints 與 rubric；高風險配方、特殊族群、疾病／用藥、醫療宣稱與版本不明法規暫不正式化。

## 三十、Sprint 36 source_verified 第二批維護規範

- 本批新增題只可由 evidence index 的實際摘錄支持；每題要保留 sourceEvidenceIds、evidenceExcerpt、answerBasis、sourceFile、sourceLabel 與 sourceConfidence。
- shortAnswer、essay、case_study 必須同步提供 referenceAnswer、sampleAnswer、keyPoints、rubric 與 explanation，供免費本機規準輔助評分使用。
- 新題使用 71001～71060 全新 ID；不得修改已作答題核心欄位、不得覆蓋原 verified／source_verified 題。既有題錯誤時使用 deprecated＋supersededBy＋新 ID。
- 高風險特殊族群、疾病／用藥、精確濃度、醫療宣稱、法規版本不明與證據不足內容不產 source_verified 題；不足時回報，不硬湊。
- Full Mock 使用 verified＋source_verified；Daily／Weekly 使用正式池加可抽練習池，仍遵守 Sprint 35B 避重與未完成保留題規則。


## Sprint 36A：非選擇題規準評分與來源

本機規準評分只供學習參考，不是正式答案判定；空白答案不執行評分。每題來源資料應優先提供 sourceFile、sourceLabel、sourcePage、sourceChapter、sourceVersion、answerBasis 與 evidenceExcerpt，缺資料必須標示待補，不得憑空補造。

## Sprint 36B：來源 metadata 補齊

- source_verified 題必須保留 sourceEvidenceIds、evidenceExcerpt、answerBasis 與來源檔案；本批可由索引明確 section 補入 sourceChapter，但不將段落定位偽稱為正式章名。

- metadata 補強不改動已作答題的 id、type、question、options、answer、referenceAnswer；若答案日後需更正，使用 deprecated／supersededBy／新 ID。
- 本 Sprint 不呼叫 OpenAI／Gemini，不修改 Apps Script；`verify:sprint36b` 必須在題庫、歷史鎖定與 production build 前後執行。

## Sprint 37：高風險教材證據正式題維護規範

- 高風險主題只要教材明確說明、sourceEvidenceIds 可回指、evidenceExcerpt 非空、answerBasis 清楚且不自行推論，即可建立 source_verified；不得因孕婦、兒童、疾病或用藥字樣自動排除。
- 高風險題一律保留 `safety_review`；該標記表示保守評分與人工抽查，不得被解讀為醫療建議或安全保證。
- 孕婦／兒童題只重述教材安全原則與詢問項目；疾病／用藥題只考評估、界線與轉介；不得生成診斷、治療、停藥或交互作用結論。
- 新增非選擇題必須有 `referenceAnswer`、`sampleAnswer`、`keyPoints`、`rubric`、`commonOmissions` 與 `teacherExplanation`，並由本機規準提供 0～3 分學習結果。
- `verify:sprint37` 必須確認 evidence 完整、正式池邊界、Answered Question Lock、scheduler、Apps Script、API Key 與 production private source bundle。

## Sprint 38：品質治理維護規範

- 品質修正優先採可逆的執行期治理層；不得為語氣、繁簡轉換或解析輔助而覆寫已作答題的核心 JSON 欄位。

- `sourceFile`、`sourceChapter`、`sourceVersion`、`sourceEvidenceIds`、`evidenceExcerpt` 與 `answerBasis` 必須保有欄位。資料不足時以「待補」與 `metadata_missing` 表示，不能以模型推測補值。
- 每次題庫治理後必須執行 `verify:sprint38`，確認 active 題沒有「依教材證據」題幹、簡體字、未處理圖片依賴或已完成題重抽；並回歸 Answered Lock 與 Coach Test 隔離。
