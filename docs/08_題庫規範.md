## 正式題庫欄位與整合門檻（Sprint 24D）

- 正式整合題目須有唯一數字 `id`、`type`、`question`、`answer`、`difficulty`、`sourceType`、`sourceLabel`、`reviewStatus`。
- 新整合題型統一使用 `multipleChoice`、`multiSelect`、`shortAnswer`、`essay`、`case`、`case_study`；Week1 舊命名由 Question Engine 相容，不修改既有題目。
- 正式 runtime 只讀取 `reviewStatus = verified` 且非 `sourceType = mock` 的題目。
- `needs_review` 與 mock 題留在 staging；mock 的 `sourceLabel` 必須是「模擬題（非歷屆試題）」。
- 對外題庫不得包含 `private/` 路徑、原始 PDF／DOCX 路徑或其他私人來源位置。

## Sprint 24E Week1 容量規則

- Daily Task v2 與 Weekly Review 僅讀正式 verified pool；題庫不足時提供可用題數並提示，不能以重複題或 needs_review 題湊數。
- Weekly Review 可為複習目的重複本週正式題與錯題；這不代表 Daily Task 可重複填補每日目標。

## Sprint 25 來源分層

- `verified`：來源與答案已確認，可進正式 Daily Task、Weekly Review、完整模擬考。
- `high_priority_review`：重要或反覆概念候選，可進標示清楚的重點複習，不進正式計分模擬考。
- `mock`：只作模擬練習，`sourceLabel` 必須為「模擬題（非歷屆試題）」。
- `blocked`：來源、答案或題型不足，不得出題，等待人工確認。
- 分層不代表答案驗證；只有人工確認後才可將候選升格 `verified`。

## Sprint 26 外部資料匯入門檻

- 外部資料庫的 canonical 候選即使有來源答案，也必須補來源頁／版本與人工核對紀錄後才可 verified。
- 備份、鏡像、重複檔案只作索引，不得重複轉題；可能衝突素材先列 high_priority_review 或 blocked。

## Sprint 26A 候選題去重與人工升格

- `week2.staging.json` 與 `pending-review.json` 的相同 candidate ID 必須先在 `docs/26A_候選題去重報告.md` 完成去重決策；報告不等於刪除資料。
- 人工核對完成前，候選維持 `high_priority_review`、`mock` 或 `blocked`，不得進正式計分池。
- 只有填妥 reviewer、decision、verifiedAnswer、notes，並補齊 sourceFile、sourcePage、sourceLabel、answer 與 `reviewStatus=verified`，才可建立匯入 patch。
- mock 仍固定標示「模擬題（非歷屆試題）」；blocked 不得出題；缺答案或來源衝突不得升格。

## Sprint 28：AI 教材題庫工廠 v2 規範

- AI 題統一使用 `sourceType=ai_generated_from_material`、`sourceLabel=教材 AI 萃取練習題（非歷屆試題）`、`reviewStatus=needs_review`、`practiceOnly=true`、`formalScoreEligible=false`。
- 安全／禁忌／濃度／孕幼／疾病注意／轉介題可進 examPractice，但必須 `riskLevel=safety_review`，不得產生診斷或治療承諾。
- 題庫工廠可使用模板生成題型變體，但需以 normalized 題幹去重；不得以變體數量把 AI 題升格 verified。

- 題庫工廠只能擴充 practice-only 題；`practiceOnly=true` 與 `formalScoreEligible=false` 為必要閘門。
- `extracted_material` 使用「教材萃取練習題」、`high_priority_review` 使用「高機率考點練習題（待人工核對）」；`mock` 使用「模擬題（非歷屆試題）」。
- 缺答案、答案衝突、blocked 或無法回溯來源的候選不得進入 `examPractice`；不得以數量目標升格 verified。

- approved candidate 仍須通過來源頁／版本、答案與人工決策閘門；`approved-candidate` 不等同 runtime `verified`。
- 與既有 verified 題 exact match 的候選保留既有正式題，不重複匯入。
- 醫療、禁忌、安全與專業核對標籤題不得因答案欄位存在就升格。

## Sprint 29：弱科與實戰題規範

- 植物油、配方、案例、法規／IFA、諮詢、職業倫理與精油個論題一律維持 `ai_generated_from_material`、`needs_review`、practice-only。
- 案例、諮詢、轉介與安全限制題預設 `riskLevel=safety_review`；解析需包含評估、紀錄、停止操作或轉介界線，不得診斷或治療宣稱。
- 植物油題優先測脂肪酸、質地、氧化、保存、過敏與調和條件；表格中的身體作用不可直接改寫成醫療宣稱。
- 缺答案、衝突、blocked 或 mock-only 資料不得作為已確認答案；mock 必須標示「模擬題（非歷屆試題）」。
- Sprint 29 題數閘門為 680～730；數量目標不構成 verified 核准，仍需人工核對來源頁、版本、答案、風險與重複。

## Sprint 30：Week5／Week8 收斂規範

- Week5 配方題需保留濃度計算、介質、部位、年齡、禁忌、替代與紀錄條件；教材中的個案比例只能作為 `needs_review` 參考，不能當成通用處方。
- Week8 綜合題可整合安全、精油、植物油、案例、諮詢與倫理，但必須標示教材 AI 練習題，不能偽裝官方或歷屆考題。
- Sprint 30 題數閘門為 1000～1050；新增題型最低檢查為 multipleChoice100、multiSelect60、shortAnswer40、case_study60、essay20。
- `practiceWeek=week-5` 與 `practiceWeek=week-8` 為獨立 routing；安全題仍可標 `safety_review`，不得因風險標記被錯分到 Week4。

## Sprint 31：品質抽查與人工決策閘門

- 1,021 題 examPractice 維持 practiceOnly；抽查與近似題掃描不得改變 verified pool，Full Mock 仍限 verified。
- `unsafe_candidate`、`needs_fix`、`duplicate_candidate` 與 `verified_candidate` 是審核工作標記，不是 runtime 核准狀態；任何候選都不得自動升格。
- 安全題、案例題、配方題與轉介題先核對風險、來源版本與保守措辭；不得使用「平衡荷爾蒙」等未經確認的治療式表述。
- exact／near duplicate 需人工確認題型、來源與作答紀錄後才可封存；不得因題幹換一種模板就視為新知識點。
- sourceFile 可追溯但 sourcePage 缺漏時，維持 `needs_review`；不得猜填頁碼或把缺頁候選列為已確認正式題。

## Sprint 31A：清理與封存 metadata

- `qualityStatus=unsafe_candidate` 或 `qualityStatus=duplicate_candidate` 的題目必須同時設 `isActive=false`、`excludeFromPractice=true`，不得進 Daily／Weekly practice pool。
- `duplicateOf` 指向保留的 canonical 題；原題不直接刪除，除非另有來源與作答紀錄移轉方案。
- 與 verified 題有學習價值的 practice 副本可使用 `sourceType=verified-practice`、`qualityStatus=near_duplicate_review`、`relatedVerifiedId`，但不得列入 verified count 或正式成績。
- `verified_candidate` 只代表待人工決策；20020 不因清理 Sprint 自動升格。
- Full Mock 的正式池仍只使用 verified 題，清理 metadata 不得改變 formal pool。

## Sprint 31C：未作答與練習結果規範

- 考試進行中不得顯示未作答題的正確答案、參考答案或解析；交卷後所有題目均可展開學習內容。
- 狀態分為答對、答錯、未作答、待自評。未作答不等同答錯、不算完成，也不直接加入錯題本。
- Daily Task 未作答題進入未完成保留題，下一次每日任務優先安排；完成實際作答後才移出。Weekly Review 可將未作答題列入後續複習候選。
- 空白選擇題與空白非選擇題均以未作答保存；有文字的 shortAnswer／essay／case_study 為待自評，不列入自動正式分數。
- 前端同步記錄每題 `status` 與空答案；Apps Script 未修改，正式統計仍須以 verified 與 `formalScoreEligible` 邊界為準。

## Sprint 32：非選擇題學習內容與 AI 評分規範

- shortAnswer、essay、case、case_study 交卷後必須有參考答案、高分示範答案、評分重點、常見漏答提醒、老師解析與來源說明；缺頁碼顯示「待補」，不得留白。
- `sampleAnswer`、`keyPoints`、`rubric`、`commonOmissions` 是學習輔助 metadata，不是 verified 正式答案；既有 answer 不因 AI 輔助而改寫或升格。
- AI 評分採 0～3 分：3 掌握、2 大致掌握、1 部分掌握、0 未掌握；資料不足、安全／法規風險或信心不足時使用「需人工確認」與 null 分數。
- AI 評分不得混入 multipleChoice／multiSelect 自動判分正確率，不得寫入正式 verified 成績；僅作為本次學習表現與後續複習優先權參考。
- AI 輸入必須同時包含題目、使用者答案、參考答案、示範答案、評分重點、rubric、分類、來源與風險；不得憑空猜測或提供診斷、治療、危險配方建議。
- AI API 金鑰只能存在 Apps Script Script Properties；前端只呼叫既有 `/exec` 代理，未設定金鑰時必須安全停用。

## Sprint 33：AI 健康檢查與安全邊界

- 健康檢查只在 `coach-test` 模式顯示，固定測試題標示為非正式題，不得進入 Bella 學員流程或正式題庫。
- 健康檢查只驗證 proxy、回傳格式、風險旗標與 0～3 分邊界；不寫入 AI 評分本機紀錄、不進錯題本、不進未完成保留題。
- provider 回傳非 JSON、缺欄位或來源／安全資訊不足時，前端必須顯示暫時不可用或需人工確認，不得強迫給分。
- AI 金鑰只放 Apps Script Script Properties；未重新部署 Apps Script Web App 前，健康檢查不得宣稱實際 AI provider 已啟用。

## 二十五、Sprint 33A 本機規準輔助評分

- 現階段非選擇題預設使用本機規準輔助評分，不呼叫 OpenAI／Gemini，也不要求任何 API Key；畫面必須明確標示「規準輔助評分」，不得偽裝成雲端 AI 深度理解。
- 評分輸出沿用 `AiReviewRecord`，新增 `gradingMethod=local_rubric`、`gradingMethodLabel=規準輔助評分`；0～3 分只代表學習參考，`needs_human_review` 使用 null 分數。
- 文字比對需先正規化全形／半形、空白、大小寫與常見中文數字；以核心概念、同義詞群與 keyPoints 命中為主，referenceAnswer／sampleAnswer 僅作輔助，不以整段字串相似度直接給高分。
- 偵測到否定、危險醫療宣稱、未稀釋／高濃度、忽略病史／禁忌／轉介或自我診斷時，不得給 3 分；依風險回傳 0 分或「需人工確認」。
- essay 過短、case 缺安全／轉介／追蹤、配方題出現無法可靠判斷的精確濃度，以及法規來源不足時，採保守扣分或人工確認；不得產生新的醫療或配方建議。
- 規準分數不得修改 selectedAnswer、correctAnswer、isCorrect，不得寫入正式 AnswerRecords，不得混入 verified 正確率或自動升格題目；Full Mock 仍 verified-only。

## 二十六、Sprint 34 正式題庫升格與每日任務上限

- Daily Task 的基本目標固定為 30 題；90 題是使用者主動加做的單日最高上限，不是強制目標。未完成保留題優先於新題，超過 90 題需分批安排。
- verified 正式題新增檔 `src/data/questions/verified-extra.json`，本 Sprint 正式總數為 150 題。補充題必須具備 `reviewStatus=verified`、`verifiedBy`、`verifiedAt`、來源標籤、答案／解析與 `sourcePage`；頁碼未知填「待補」。
- AI 教材萃取題只有在題型、答案、選項唯一性、解析、來源檔案與風險閘門均通過時，才可進入本批保守升格；來源標籤仍須明確寫「非歷屆試題」，不得描述為官方或歷屆題。
- 禁止升格 safety_review、mock、unsafe、duplicate、缺來源、答案不明、法規版本不明、醫療宣稱、危險濃度、孕婦／兒童／疾病／用藥交互作用與轉介判斷題。這些題維持 examPractice 並等待人工覆核。
- 升格來源的原 examPractice 題不得繼續進練習池；以 `promoted_to_verified`、`relatedVerifiedId`、`isActive=false`、`excludeFromPractice=true` 保留追蹤，不能直接刪除歷史資料。
- Full Mock 只讀 verified；Daily／Weekly 可讀 verified 加上符合練習閘門的 examPractice，且合併後 ID 必須全域唯一。規準輔助評分仍不影響 verified 正確率。

## 二十七、Sprint 34A verified 覆核與降級規範

- Sprint 34 新升格題必須逐題通過題幹清楚、答案唯一／充分、解析一致、來源可追溯與非高風險等檢查；批次閘門通過不等於人工正式核准。
- 題目含「尚待人工核對」、合成式題幹、無關共用干擾選項、答案直接重複題目主題或非選擇題答案只有主題名稱時，不得留在 Full Mock。
- `downgrade_to_practice` 題恢復 `practiceOnly=true`、`formalScoreEligible=false`、`reviewStatus=needs_review`；`hold_for_human_review` 題不得進 verified，需於文件中保留原因。
- `remove_or_disable` 題不得抽入 Daily／Weekly／Full Mock，使用 `isActive=false`、`excludeFromPractice=true` 與 `qualityStatus=needs_fix` 保留追蹤，不直接刪除歷史資料。
- verified 題數不足時不得以未核對的 AI 題補數；正式模擬考可信度優先於題數，原 verified 答案除非有明確錯誤不得修改。

## 三十、Sprint 36 source_verified 第二批規範

- source_verified 題必須具備 `verificationType=source_verified`、`sourceEvidenceIds`、非空 `evidenceExcerpt`、`answerBasis`、`sourceFile`、`sourceLabel` 與 `sourceConfidence`；low confidence 不得進正式池。
- 第二批非選擇題必須具備 `referenceAnswer`、`sampleAnswer`、`keyPoints`、`rubric`、`explanation`，供本機規準輔助評分使用；分數仍不是 verified 正式分數。
- 新題必須使用全新 ID，不得覆蓋已作答題。既有題目若需修正，保留舊題並以 deprecated／supersededBy／新 ID 處理。
- Full Mock 使用 verified＋source_verified；一般 examPractice、needs_review、practiceOnly、safety_review、mock、duplicate、inactive、unsafe、deprecated 一律排除。
- 缺 evidence、來源定位不足、答案衝突或涉及高風險特殊族群、疾病、用藥、精確濃度、醫療宣稱與版本不明法規時，不產 source_verified 題。

## 三十一、Sprint 36B 來源 metadata 規範

- 正式題池 metadata 補強只可新增來源資訊，不得修改題目核心欄位；已作答題保留原題與歷史解析。
- `sourceChapter` 若來自 evidence index 的 section，必須保留原始段落定位，不得把段落號改寫成推測章名。
- `sourcePage`、`sourceVersion`、`answerBasis`、`evidenceExcerpt` 沒有實際證據時顯示「待補」，不得以檔名、索引建立時間或 AI 解釋猜造。
- source_verified 的 evidence IDs 必須可對應索引；正式題池驗證由 `verify:sprint36b` 檢查，Full Mock 仍只使用 verified＋source_verified。

## 三十二、Sprint 37 source_verified 第三批規範

- 孕婦、兒童、疾病、用藥與比例題不再因主題本身自動排除；只有教材明確說明、具 evidenceExcerpt、answerBasis 且答案不自行推論時，才可建立 source_verified。
- 孕婦只考教材列出的安全詢問；兒童只考教材明確的年齡／使用原則；疾病只考安全界線與轉介；用藥只考病史／用藥詢問與轉介，不提供停藥建議。
- `safety_review` 在本批表示需保守作答與後續抽查，不等同於 `practiceOnly`；只要 `verificationType=source_verified`、`formalScoreEligible=true`、`practiceOnly=false` 且 evidence 完整，仍可進正式池。
- 精確比例只可重述教材既有比例或概念，不得生成個人化疾病配方；醫療宣稱只能作為倫理界線的反例，不得作為答案結論。
- 新批次使用 `72001`～`72100`，既有已作答題仍受 lock 保護；修正一律建立新題或 deprecated，不覆寫核心欄位。

## 三十三、Sprint 38 品質治理與重複控制

- active 題幹不得依賴未隨題提供的圖片；若無原始教材／考題圖片，必須改為可獨立作答的文字題，不得以 AI 圖替代。
- 「依教材證據」只可存在於來源、解析與答案依據，不得出現在使用者可見的 `question`；中文顯示欄位必須為繁體中文，英文學名維持原文。
- 正式非選擇題必須可提供參考答案、示範答案、評分重點、解析與 0～3 分 rubric；既有來源不足時以 `metadata_missing`／「待補」標記，禁止虛構。
- 已作答題的核心欄位絕不由品質治理層改寫；需修正時建立新題或 deprecated。
- Daily／Weekly 除未來明確核准的最後一週總複習模式外，不得抽取 `isCompletedOnce` 或 `completedCount > 0` 的已完成題；近 3／7 日避重與未完成優先規則仍適用。
## Sprint 35：教材證據式正式題庫與歷史保護

- 建立 source_verified：84 題；每題具有實際 evidenceExcerpt、answerBasis、sourceEvidenceIds 與來源檔。
- 人工 verified 仍為 41 題；Full Mock 使用 verified + source_verified，共 125 題。
- Daily／Weekly 使用正式池 + 974 題可抽 examPractice，共 1,099 題；30／90 題規則不變。
- 原訂 120 題未達，因高風險、片段黏連、答案衝突或來源不足而排除，禁止為數量硬湊。
- 已作答或可能同步過的既有題目核心欄位不可修改；錯題採 deprecated + supersededBy + 新 ID。
- source_verified 與人工 verified 分層，無需逐題人工確認，但必須可由教材證據直接支持。
